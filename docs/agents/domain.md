# Domain docs

## Before exploring the codebase

Use a single-context layout for this repository:

- Read `CONTEXT.md` at the repository root when it exists.
- Read decisions in `docs/adr/` that concern the area you are exploring.

If these documents do not exist, proceed silently. The `domain-modeling` skill creates them when domain terms or decisions are resolved.

## Domain vocabulary

Use the terms defined in `CONTEXT.md` in issue titles, proposals, hypotheses, tests, and code. If a needed concept is missing, check whether it belongs to the domain and record the gap for `domain-modeling`.

## ADR conflicts

If a proposal contradicts an existing ADR, identify the ADR and explain why its decision should be reconsidered.
